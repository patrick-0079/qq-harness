正式实例的 OpenCode Go 查询存在间歇性失败：本轮通过只读运维接口先取得成功结果，随后再次复现原来的 failed 提示，之后恢复成功。相同凭据的独立请求返回 HTTP 200，响应包含 rolling、weekly、monthly，说明当前地址、凭据和解析格式可以正常工作。原版本没有保存底层错误类别，无法据此确认失败究竟来自连接中断、DNS、TLS 还是异常响应，不能断言具体网络根因已查明。

## 已完成的修复

- 只读渠道 GET 遇到连接中断、解析失败、网络超时、临时网关错误或非 JSON 响应时最多重试一次；所有尝试共享原配置的总超时。401/403、限流与证书错误不盲目重试。
- 临时失败、超时或取消不再缓存 60 秒，网络恢复后可立即重新查询。成功和认证失败仍保留缓存与并发合并。
- 返回受控的 DNS、连接、TLS、HTTP、非 JSON 和渠道字段提示，不回显原始异常、响应正文或凭据。
- 修正私聊余额查询失败仍被记录为指令成功的问题，其他渠道仍独立返回结果。
- 英文运维命令统一接受大小写，渠道与凭据去除首尾空白，避免空白凭据误判为已配置；布尔值不能被解析为零余额或零用量。
