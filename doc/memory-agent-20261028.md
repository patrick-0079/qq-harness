# 独立记忆 Agent 与分层文档

2026-10-28。本文描述当前实现，替代旧版“对话工具直接写入、所有层级先降为短期”的运行方式。没有执行旧的生产迁移脚本。

## 数据与职责

短期记忆和草稿本保留条目；中期、长期是按主题组织的 Markdown 文档。文档正文与标题、主题、可见范围、修订、来源一起保存在现有 SQLite 或文件仓储中，并非散落的 `.md` 文件。旧中长期正文保持原层级，首次启动增加文档元数据并保留历史修订。旧文本记忆在启动或提交申请时导入，GET 不导入、不清理、不推进游标。

对话模型、用户界面和兼容扩展均向独立维护者提交申请。维护者读取当前人设、记忆索引、相关正文、草稿、新消息证据和遗忘账本，通过自己的工具暂存变更，最后以一次事务提交。对话工具不暴露维护工具。SQLite 和文件仓储均支持失败回滚。

维护由模型完成语义判断：相同主题合并到已有文档，变化的结论更正原文，其他段落保留；需要使其他层旧结论退出时提交 `supersedes`。用户指定层级时禁止越层写入。文档过长时维护者可以拆分主题，避免形成一份无限增长的总文档。

申请状态为 `queued → running → completed / needs_clarification / failed / cancelled`。受理返回 202 与申请 ID，不代表已记住或已遗忘。需要澄清时暂存内容不提交；失败和取消可以补充说明后重试。运行容量不足保留队列；进程关闭后下次启动恢复未完成申请。任务提交与记忆变更共用事务，重复幂等键不会重复执行。

## 人设与遗忘

选定的人设模板初始化长期的“人设与自我认知”文档。维护者结合现有自我认知取舍记忆，例如胆小人设更倾向淡化恐怖细节。文档可演进，模板仍只读。

切换人设 ID 时，从新模板重新初始化该文档。切回旧 ID 也重新初始化；保存相同选择不会重置。其他知识、经历、短期条目和草稿保留。每次切换有独立 epoch：旧任务在提交前发现 epoch 变化会丢弃暂存结果并重新排队，不能将旧自我认知写回。

“遗忘中期记忆：火箭速度 2 km/s”应仅移除中期匹配内容，保留其他段落和较新速度。部分遗忘通过文档更正和 `forgottenText` 记录账本；整项遗忘保留逻辑删除历史。账本向维护模型提供语义约束，同时拦截同层旧原文的直接重写。语义改写仍由模型判断，任务结果与前后差异可在界面复核。

## 对话模型接口

| 工具                    | 用途                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------- |
| `memory_search`         | 回答历史事实、偏好、约定等问题前检索当前获准范围                                    |
| `memory_get`            | 按 ID 读取有效条目、文档或草稿的正文、来源与版本                                    |
| `memory_request`        | 自然语言申请新增、更正、融合、遗忘或草稿维护；可指定层级、目标 ID、真实消息 localId |
| `memory_request_status` | 查询实际完成情况、错误或待澄清问题                                                  |

系统提示词明确引导先查询、发现变化后提交申请、受理时不宣称完成。`memory_append/query/remove` 仅为兼容保留，不列入对话模型工具；兼容扩展的修改也提交异步申请。

维护者私有工具：`memory_inspect`、`memory_write`、`memory_forget`、`scratchpad_write`、`memory_finish`。修改既有正文必须提供当前 `expectedRevision`；来源、会话、层级、人设 epoch 在提交时校验。`personId` 接受数字字符串或可安全表示的正整数，整数规范化成字符串。

## HTTP 与界面

所有接口归 `agent-memory` 插件，受管理鉴权与会话准入约束。参数错误返回 400，操作冲突返回 409。错误使用 `{error:{code,message}}`，前端展示可读信息。

| 接口                                                         | 当前行为                                                                                   |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| `POST /api/memory/requests`                                  | `{chatKey,instruction,tier?,sourceIds?,targetIds?,idempotencyKey?}`，202 返回申请          |
| `GET /api/memory/requests?chatKey=…`                         | 本会话申请及实际变更摘要                                                                   |
| `GET /api/memory/requests/:id?chatKey=…`                     | 单个申请状态                                                                               |
| `POST /api/memory/requests/:id/clarify`                      | `{chatKey,instruction}`，补充说明或重试，202                                               |
| `GET /api/memory/records?chatKey=…&tier=…`                   | 当前指定层级；`history=1` 返回历史记录                                                     |
| `GET /api/memory/documents?chatKey=…&tier=…`                 | 仅文档                                                                                     |
| `GET /api/memory/documents/:id?chatKey=…`                    | 单份文档                                                                                   |
| `GET /api/memory/{records\|documents}/:id/history?chatKey=…` | 正文修订历史                                                                               |
| `GET /api/memory/search?chatKey=…&query=…`                   | 过滤权限后的检索                                                                           |
| `GET /api/memory/notes?chatKey=…`                            | 草稿本条目；支持 `history=1`                                                               |
| `GET /api/memory/notes/:id/history?chatKey=…`                | 草稿本修订                                                                                 |
| `POST /api/memory/consolidate`                               | `{chatKey,tier?}`，202 返回申请 ID；不指定层级时依次提交短/中/长期，返回 `id` 与完整 `ids` |
| `GET /api/memory/consolidation?chatKey=…`                    | 整理计划、失败信息、活动运行 ID                                                            |
| `GET/PATCH /api/memory/settings`                             | 默认配置、会话覆盖和有效配置，沿用整理时间与保留期限                                       |
| `GET /api/memory/status`                                     | 索引健康状态                                                                               |

旧的条目/草稿 POST、PATCH、DELETE，以及 `/api/chats/:chatKey/memory` PATCH，仍可调用，但统一返回 202 申请，不再返回同步修改结果。旧草稿撤销接口只撤销待发布操作，不直接发布记忆。内部低层仓储接口用于维护者和迁移，不提供给对话模型。

会话“记忆”页分为“记忆管理 / 记忆设置”。管理再按短期、中期文档、长期文档、草稿本切换；支持自然语言申请、Markdown 预览、来源与版本差异、失败原因、补充说明和重试。明确写出层级的自然语言申请优先采用该层级。

## 验证与部署边界

新增回归覆盖语义融合调用契约、定层遗忘、来源与隐私、双仓储事务回滚、人设演进与切换、旧任务拦截、关闭恢复、澄清、数字 personId 和 GET 只读。自动化只使用 mock 模型，不证明某个实际模型每次都能正确语义融合；实际任务保留差异供复核。

首次启动会加文档元数据与维护控制状态。上线前备份目标配置及一致性数据库/文件仓储；回滚必须同时恢复配置、存储和匹配的构建。旧 `upgrade-management.ts` 含中长期降级逻辑，不能当作本次记忆升级脚本运行。
