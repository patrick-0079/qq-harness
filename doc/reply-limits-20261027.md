# 回复条数、批量引用与会话正文空间（2026-10-27）

本批只修改 `qq-harness`。参考用户提供的 `group:10001` 页面做只读布局检查，没有向真实会话发送测试消息；自动化使用独立数据和 mock QQ、SnowLuma、网络及模型。

## 每轮回复消息上限

入口：**会话 → 设置 → 聊天策略 → 每轮回复消息上限**。默认会话也提供同一入口；保留完整快照语义，已有独立会话不随默认配置改变。聊天分区恢复默认时会恢复该字段。

配置字段 `ChatSettings.maxReplyMessages`，整数0–100，默认0表示不限。未指定次数，不替用户选择一个有限值；现有会话兼容为不限。设置后对下一轮开始的Agent回复生效，运行中不会重置或放大发送额度。

```json
{"maxReplyMessages":3}
```

单会话通过 `PATCH /api/profiles/:chatKey` 保存；全局默认通过 `PATCH /api/config` 的 `defaults.maxReplyMessages` 保存。非法负数、小数、字符串和超过100的值拒绝保存。

模型每轮请求都会看到明确提示，例如“本次回复最多发送3条信息，已发送或结果待确认1条，剩余最多2条”。提示放在会话扩展重建上下文之后，旧额度块被替换，不反复叠加。

发送队列强制执行，不能仅靠模型自觉：

- 同一Agent运行内，文字、图片、表情、拍一拍等产生新聊天消息的发送合计计数，跨多次工具调用共享。
- 跨会话和扩展子操作按父运行关联共用额度；不同发送队列并发时，提交协议前原子占用额度。
- 长文字的管理员硬拆分按实际消息数计数，不按最外层数组元素数量计算。
- 去重不消耗新额度；协议明确拒绝时退还，结果未知时保守占用，避免重试超发。
- 输入状态、表情回应和资料修改不产生新聊天条目，不占消息条数。人工管理发送和独立提醒不属于同一Agent回复，不被这项配置截断。
- 用完后工具返回上限原因，明确禁止继续发送或重试；模型仍可调用finish作正常收尾。`stop=true` 保持原有直接结束语义。

公开发送服务增加可选 `openReplyBudget` 能力，Agent在本轮开始建立、结束释放。启用限制而发送提供者缺少此能力时停止运行，不能悄悄忽略限制。额度是运行期状态；原 `outbound-attempts` 继续记录成功、明确失败和未知发送，没有新增独立数据库。

## 同一批回复只给首条加引用或 @

原实现把 `replyToMessageId` 或 `atUserId` 加到messages数组每个元素，导致整批都显示引用。现在仅数组首条使用引用／@，后续元素按普通消息发送；两参数仍互斥，引用仍须属于当前会话。

```json
{"messages":["回应这一条","接着正常补充","最后一条"],"replyToMessageId":"原消息ID"}
```

上述只有第一条引用原消息。系统提示和工具说明同步注明，不要求模型自行给后续每段重复引用。模型、网络或协议的重试不会自动重发已经成功的项目。`send_message.sent` 同时修正为实际新增的物理消息数，去重项不虚增，硬拆分能正确统计。

## 上方占高、下方正文拥挤

只读复现时，在1366×768窗口，运行面板从y=297到622，正文时间线直到y=499才开始，可见高度约123px；ID、日期、标签、导出栏和重复间距占掉大半区域。

本批调整：

- 会话页去掉重复副标题，压缩会话标题栏；长名称单行省略、悬停查看完整名称，操作不被长名称挤到多行。
- 运行ID与复制在一行，状态／时间在紧凑摘要行；导出与详情页签合并，不再单独占整行。
- 日期筛选收入“日期范围”展开区，搜索和状态仍直接显示；清除和已筛选状态保留。
- 删除旧元信息区多余16px底部padding，正文不再为它反复让位。
- 手动触发的顶部反馈只显示“已提交”，完整ID保留在悬停与无障碍标签中，可在运行详情复制，避免UUID撑开标题栏。
- 触发事件的完整配置快照默认折叠。消息、上下文、模型请求、工具调用仍按原轨迹保留，配置、原始数据和导出均可查看。

新增浏览器几何断言：长名称时标题栏小于80px，详情上部小于125px，正文至少占运行面板60%；保存、日期筛选、清除日期和导出入口仍可操作。
