# 系统上下线与运维控制台

系统上下线由原生 `system-control` 服务统一执行。关闭可选的 `ops-control` 运维插件不会恢复发言；网页顶栏的系统控制仍然可用。

## 上下线规则

- 下线立即关闭普通运行准入，取消执行、排队、聚批及延迟发送；QQ、SnowLuma、HTTP 和消息存档继续运行。已经提交给协议端的消息无法撤回。
- 所有出站动作均复查状态；运维回执需要绑定真实运行、原私聊、固定文本的一次性授权，工具参数不能声明豁免。
- 记忆 Agent 继续按照现有记忆开关与准入维护记忆，可能产生模型费用。
- 上线跳过旧消息和过期提醒，不改变单会话上下线、准入与黑名单。过期定时任务推进调度并记录跳过；不会集中补发。
- 状态、版本及切换信息持久化，重启后保持。首次迁移优先保留下线状态；旧运维插件的执行入口停用，配置留作追溯。

## 使用入口

顶栏提供系统状态及上下线按钮；`/operations` 提供状态诊断、资源占用、用量余额、操作记录与设置。运维页面由插件注册，无内容区重复大标题。

仅专用白名单 QQ 的私聊可执行 `/ctrl 状态`、`下线 [原因]`、`上线`、`系统`、`诊断`、`用量`、`余额 [渠道]`、`帮助`。群聊不执行运维指令；空名单或关闭私聊开关时不提供私聊控制。控制不依赖普通聊天准入，但仍受启动边界和显式黑名单限制。

余额支持 OpenCode Go、DeepSeek、GLM、MiMo 的既有接口，按需查询，缓存 60 秒；渠道独立超时。凭据只通过专用设置接口保存，读取时脱敏，不进入模型上下文。部分渠道失败不影响其他结果；缺少计价信息的本地用量不估算费用。

## 接口

- `GET /api/system/presence`：系统状态、版本、切换时间、来源、操作者和原因。
- `PUT /api/system/presence`：`{ state, requestId, expectedRevision?, reason? }`；操作者由入口确定。状态变化时递增版本；幂等标识不能复用于不同操作。
- `/api/status` 增加 `presence`、`memoryMaintenance`；`paused` 保留为兼容映射。
- 旧 `/api/pause` 转接统一控制；恢复时要求跳过积压，显式请求补处理返回 400。
- `/api/operations/status|resources|usage|logs|settings` 提供运维数据；余额使用 `POST /api/operations/balances`，设置使用 `PATCH /api/operations/settings`。
- 普通配置 API 禁止修改系统状态与运维设置；基础系统控制插件不能通过插件管理 API 停用。

## 验证与发布

自动化测试使用隔离数据、mock 模型和 mock 网络，覆盖取消竞态、队列满时控制、权限、重启、积压、提醒、定时任务、记忆、余额与页面。

正式发布前运行完整版本验收，停机创建一致性数据快照并备份扩展索引，再原子切换发布指针。回滚只切换代码指针，不恢复旧数据库覆盖新增数据。

人工真实 QQ 联调工具：`node --import tsx tools/verify-system-control-live.ts --live`。使用独立数据和 mock 模型，仅连接用户指定的私聊 10002、群聊 10001；既有白名单包含测试私聊时，在隔离配置中开启入口验证恢复，不修改生产白名单。模拟入站与真实 QQ 出站在证据中明确区分。
