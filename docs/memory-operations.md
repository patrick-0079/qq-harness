# 记忆运行手册

这份手册针对 `qq-harness` 独立数据目录。**不要**把 `HARNESS_DATA_DIR` 指向旧部署的 `source/data`，也不要在旧机器人仍消费同一 QQ 账号时启动新 live 实例。项目验证只使用临时目录、mock 网络与 mock 模型。

## 启用与观察

默认装配顺序是存储提供 `MemoryRepository`，`memory-index-lexical` 提供 `MemoryIndex`，`agent-memory` 提供服务、工具、路由和页签。插件管理页可以停用记忆插件；停用后的权威数据保留。会话页「记忆与暂存」展示提供器、是否就绪和 `pending` 事件数，每 5 秒刷新一次；也可请求 `GET /api/memory/status`。

在默认 demo 下，记忆查询、人工写入、记事本和重启持久化均可验证。mock 模型对自动提炼返回空候选，不会凭演示消息生成真实偏好。真实模型的自动提炼需要显式 live 配置及会话准入。后台每 5 分钟巡检未处理消息、到期暂存、待提升条目和索引事件；累计 30 条入站消息会提前触发该会话提炼。

## 数据、备份与升级

| 数据                                   | SQLite 模式                              | 文件模式                   |
| -------------------------------------- | ---------------------------------------- | -------------------------- |
| 原消息、旧文本记忆                     | `harness.sqlite` 的 `messages`、`memory` | 原文件存储布局             |
| 结构化事实、修订、暂存、游标、索引事件 | 同库 `memory_*` 表                       | `memory-system/store.json` |
| 词面索引                               | 插件内存，启动重建                       | 同左                       |

SQLite schema version 2 创建新表，原 `memory` 表不删除也不复制。升级前对**独立新工程**数据做一致性备份；使用 [SQLite 运维](storage.md#备份与体检) 的 backup 命令，另行保留 `config.json`。文件模式应在停服后备份数据目录。备份包含聊天、事实与修订，属于敏感数据；不要提交到 Git 或上传公共工单。

迁移旧部署数据应先使用 [离线导入工具](storage.md#离线导入旧数据)处理副本并核对数量。导入后的旧文本通过兼容 API 读取，新结构化记忆不会凭旧文本自动生成。向量索引或其他新索引都必须能由权威仓储重建；索引不是备份来源。

## 故障判断

| 现象                         | 核对与处理                                                                                                                                               |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ready:false` 或索引启动失败 | 查看插件日志。查询会回退权威仓储词面检索。检查提供器能否重建；重新启用插件或重启独立实例可触发全量重建。                                                 |
| `pending` 持续增长           | 索引事件消费失败或索引提供器不可用。事实写入仍完成；恢复后重放事件或重启重建，核对 `pending` 归零。                                                      |
| 消息已到但无自动事实         | 确认会话准入、是否为入站消息、5 分钟/30 条触发条件、模型配置和日志。空候选不表示处理失败；可用游标与新消息测试。不要把 mock 模型的空结果当真实提炼效果。 |
| 搜不到某条事实               | 核对会话及成员身份、来源会话准入、敏感和可见性、到期与状态、查询是否有词面重合。`personId` 必须属于当前会话；中文同义表达可能漏召回。                    |
| 暂存条目标记重要后未提升     | 查看来源 ID 是否属于当前会话真实入站消息；无证据会是 `failed`。补充证据后修改或再次标记重要。                                                            |
| 修订冲突                     | 重新读取记录，以最新 `revision` 人工合并；不要直接覆盖数据库。                                                                                           |

删除结构化事实是软删除，历史仍保留；中期到期只影响召回，暂存到期则物理删除。若需要彻底清除个人数据，应另行制定涵盖消息、事实、修订、备份和未来外部索引的删除流程；当前 API 不提供一键彻底擦除。

## 更换索引提供器

实现 `MemoryIndex` 并由 `AppOptions.memoryIndex` 装配新插件；嵌入模型通过独立 `EmbeddingProvider` 契约接入。新提供器应有稳定 `id`、修订幂等、删除墓碑、归一化分数、`allowedIds` 过滤、健康状态、可重建能力及卸载清理。更换索引提供器后权威正文不迁移。

先用同一仓储全量构建新索引，核对每条 ID、修订、删除和到期处理；写入期间继续消费索引事件。用 [评测方案](memory-evaluation.md) 比较中文查询，再切换装配，保留词面插件作为回退。外部向量服务应单独配置允许的数据范围；会话限定内容若不能外发，提供器需要本地检索分支。首版没有外部向量服务或重建命令 API，启动时由插件自动重建。

## 验证命令

在 `D:\QQAgent\qq-harness`、Node.js 24+ 环境运行：

```powershell
npm run typecheck
npm test
npm run build
npm run check:architecture
npm run test:e2e
```

浏览器 E2E 用例共用一个临时服务和其插件设置，因此配置为单 worker 串行执行。记忆专项单测使用临时数据与 mock 模型；不读取旧部署、启动用户 QQ 或调用收费模型。修改 v2 兼容层时还需运行 `npm run test:v2-reference`。
