# 真实 QQ 联调记录（2026-10-26）

用户明确授权停止旧 source 机器人，并限制只能测试一个指定群与一个指定私聊；用户另外确认已阅读并同意当前 SnowLuma EULA 和隐私政策，自行完成 QQ 登录与发送测试消息。公开文档隐去实际 QQ 号。

## 运行范围

- 旧 PM2 的 qq-agent、qq-agent-boot 均为 stopped，未修改持久化 PM2 启动编排。
- 新实例位于 http://127.0.0.1:3311，使用独立 var/real-qq-20261026 数据目录。只读提取原配置中当前模型和 OneBot 凭据，没有导入历史聊天。
- `HARNESS_ALLOWED_CHATS` 固定为两个获许可会话；配置 API 不能扩大本进程的范围。黑名单和配置准入仍参与判定。
- SnowLuma 通过独立插件管理，复用本机安装，第三方源码未修改；QQ 使用原便携实例。两个协议同意字段明确保存后才允许启动。
- 联调停用了提醒、确定性工具命令、外部原生插件发现及五个 v2 管理器，验证的是基础聊天链路。

## 结果

| 检查              | 观察结果                                                                    |
| ----------------- | --------------------------------------------------------------------------- |

发送成功依据为 OneBot 成功返回、运行实际发送计数与数据库出站记录。记录不包含真实聊天正文、账号凭据或第三方日志；没有将两个许可会话以外的账号用作主动测试目标。

## 发现并修复的问题

首次两次运行均在模型请求阶段返回 HTTP 400、发送数为 0；失败档案保留。以无聊天内容的协议请求定位到当前 OpenCode 端点强制要求 x-opencode-session。

新增 model-opencode 独立插件，通过 model-openai 提供的 model.http.headers 通用扩展点补充稳定会话头和客户端标识。官方域名使用精确/子域匹配；中转端点通过 opencode-go/ 模型前缀识别。普通端点不附加此头。插件卸载撤销贡献、重新启用生成新会话，两个联调消息重试后均通过。

回归检查：32 项 Vitest、103 项原 v2 契约断言、4 项浏览器用例、类型检查、构建和架构检查通过。新增 mock 协议回归覆盖缺少头时的 400、会话稳定、普通端点与相似域名隔离、卸载/重新启用。
