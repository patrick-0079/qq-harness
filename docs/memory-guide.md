# 分层记忆完整指南

`agent-memory` 是独立 Cordis 插件，提供 Agent 工具、后台提炼、管理 API 和会话页签。`memory-index-lexical` 是首版检索插件。短期消息从原消息仓储按需读取；中长期事实由 `MemoryRepository` 保存。Agent 每轮提示词只有查询指引，记忆正文仅在调用工具后进入上下文。

## 快速使用

1. 按 [README](../README.md#启动) 启动，在「插件」页确认 `memory-index-lexical` 和 `agent-memory` 已启用。
2. 在「会话」页打开已准入会话，进入「记忆与暂存」页签。可按 QQ 号筛选成员，查看事实来源、修订和索引状态，人工新增、编辑、提升或删除记忆。
3. Agent 遇到历史事实、偏好、约定或未完成事项时调用 `memory_search` 或 `scratchpad_list`。临时事项用 `scratchpad_upsert` 保存；有来源证据的稳定事实可用 `memory_remember`。
4. 默认 mock 模型的提炼结果为空数组，只用于验证流程。真实提炼取决于显式配置的模型与聊天准入；自动化测试不连接真实 QQ 或收费模型。

停用 `agent-memory` 会撤销服务、工具、路由、页面贡献与后台计时器。重新启用后权威数据仍在，未处理消息按持久游标继续，词面索引从仓储重建。

## 身份、范围与生命周期

`chatKey` 是会话标识，例如 `group:10001`、`private:10002`；`personId` 是 QQ 号字符串。一个事实只能处于下表的一种范围。

| 范围 `scope`  | 短期读取                 | 中期 `medium`        | 长期 `long`              |
| ------------- | ------------------------ | -------------------- | ------------------------ |
| `chat_person` | 此人在当前会话的近期发言 | 阶段性互动或角色     | 此人在当前会话的稳定特征 |
| `chat`        | 当前会话近期消息         | 话题、阶段约定与氛围 | 稳定会话规则与偏好       |
| `person`      | 不跨会话提供原始短期消息 | 可共享的阶段特征     | 稳定、非私密的通用特征   |

短期默认只读最近 **48 小时、最多 30 条**原消息；`memory_search` 的工具结果最多附带 5 条文本匹配的近期消息。短期正文不复制进记忆表或索引。中期记录必须有未来到期时间，自动生成时默认为 30 天；到期后不再召回。长期记录不自动删除，最后确认时间较旧只降低排序优先级。

中长期记录包含事实键 `key`、正文、范围、人员、证据引用、`confidence`、`importance`、敏感标记、来源方式、状态、修订号、最后确认时间和到期时间。`active` 可参与召回；`superseded` 与 `deleted` 留在历史中但退出召回。证据引用使用原消息的 `chatKey`、本地消息 ID 和发送者 ID；新增引用必须真实存在且发送者匹配。

旧会话文本仍由 `StorageService.memory/setMemory` 保存。新查询把它投影为当前会话兼容长期记录，**不复制成第二份事实**。旧 `/api/chats/:chatKey/memory`、`memory_query`、`memory_append` 保持原用法。旧文本没有逐句证据或结构化修订，建议核实后人工建立新事实。

## 自动提炼与纠错

```mermaid
flowchart LR
  A[已准入入站消息] --> B[原消息仓储]
  B --> C[按会话游标聚批]
  C --> D[模型候选]
  D --> E[证据与范围校验]
  E --> F[权威仓储及修订]
  F --> G[索引事件]
  G --> H[检索索引]
```

所有已准入的**入站**消息进入待处理范围，不要求机器人已回复。同一会话累计 30 条时立即提炼，否则约 5 分钟后处理；一次最多 30 条。启动时扫描已有会话的未处理消息。模型调用限时 60 秒，要求返回结构化 JSON；无值得保存内容时返回空数组。

候选只能引用本批消息 ID。会话成员事实必须有该成员的来源；通用个人事实只接受群聊中该人自己的证据，私聊或敏感候选不自动跨会话。推断性的长期或跨会话事实至少需要两条证据；本人明确陈述可直接形成候选。相同范围、人员、事实键和文本只合并新证据；冲突文本把旧项标为失效并创建新记录。重复读取不刷新确认时间或增加置信度。

模型解析或保存失败时不推进游标，定时或后续消息会重试；重启后也按游标继续。相同事实键和文本的重试会去重。**事实键由模型产生**：不同键描述同一语义时首版不能保证自动合并，应在管理页人工修正。批次中部分候选已写入而后续失败时，重试会根据当前权威记录重新合并。

## 会话暂存记事本

记事本按 `chatKey` 隔离，支持创建、读取、修改、删除和重要标记。默认最长保留 7 天，会话设置 `scratchpadMaxDays` 可在 1–90 天内覆盖；单条可设更短期限。期限从**最后一次修改**起算，读取不续期。读取会清理到期项，后台每 5 分钟也清理一次。

重要标记触发后台整理。只有条目关联了当前会话真实的入站来源消息，才建立或更新一条**会话中期**记忆；缺少来源时标记为 `failed`。修改或再次标记重要可重试。提升后的事实默认 30 天到期；删除暂存条目不会自动删除已提升事实，需在记忆管理页单独处理。暂存正文不进入中长期检索索引，也不单独生成跨会话个人事实。

## 召回、权重与隐私

召回首先检查当前会话准入。指定人员时，必须能在当前会话消息中确认其身份；`private:<QQ号>` 对应本人。仓储先按会话和人员产生候选 ID，排除失效、到期和不可见项。索引只返回允许 ID 的相关分数；服务重新读取权威记录并**再次**检查准入、会话、人员、来源准入、敏感性、到期和删除状态。旧索引残留或错误返回的 ID 不能越权读取正文。

非敏感 `person` 记录可跨已准入会话召回，前提是相关人员在当前会话中，且所有来源会话仍准入。`chat` 与 `chat_person` 始终只在原会话可见。私聊内容不自动提升到 `person`；人工提升应先确认非敏感。敏感检测由模型标记与有限关键词规则共同完成，**不能保证识别所有隐私信息**；真实使用前应按 [评测方案](memory-evaluation.md) 做中文样本审核。

硬过滤后才排序。当前总分为 `0.40 × 相关性 + 0.25 × 置信度 + 0.15 × 重要性 + 0.15 × 新近度 + 0.05 × 范围贴合度`，各项为 0–1。范围贴合度依次是会话成员 `1`、会话 `0.9`、通用个人 `0.8`。中期新近度按最后确认时间以 14 天半衰；长期以 90 天半衰且最低为 `0.3`。固定记录的新近度为 `1`，但不能绕过硬过滤。索引只提供相关性，替换索引不会改变事实可信度或权限规则。相关性为 0 的结果不返回。

## 权威仓储与可替换索引

`MemoryRepository` 保存完整记录、修订、暂存、处理游标、待索引事件和各提供器检查点。SQLite 默认写入 `var/local/harness.sqlite` 的 `memory_*` 表；开发文件实现原子写入数据目录下 `memory-system/store.json`。记录写入/修订与索引事件在同一次持久化操作中提交。

`MemoryIndex` 只保存可重建投影：ID、修订、文本、范围、人员、可见性及敏感标记。接口包括 `upsert`、`remove`、`search`、`rebuild`、`health`，查询只返回 ID 与 0–1 相关分数。当前 `memory-index-lexical` 用内存词面索引，中文按 1–3 字片段匹配。启动时全量重建，之后按事件同步；旧修订号不能覆盖新修订或删除墓碑。索引未就绪、积压过多或查询失败时，服务退回仓储范围内的词面检索。页面和 `/api/memory/status` 可查看索引状态。

`EmbeddingProvider` 独立定义提供器 ID、向量维度与 `embed(texts, signal)`，首版没有默认实现。未来向量库提供器应遵循：

1. 保持仓储为唯一权威数据源；向量库只存可删除、可重建的投影，并返回 ID 与归一化相关分数。
2. 在索引写入前明确哪些范围可发送外部服务。若外部服务只允许通用非敏感内容，应在同一索引提供器内对会话限定记录使用本地检索，避免它们因缺索引而无法召回。
3. 使用 `allowedIds` 做索引侧预过滤，并接受服务侧二次检查；支持幂等修订、删除、健康检查与全量重建。
4. 从仓储全量构建新索引并核对 ID/修订，用同一中文查询集并行评测，再通过 `AppOptions.memoryIndex` 切换。保留词面提供器以便回退；切换不迁移权威正文。

首版没有外部向量请求或嵌入费用。是否引入 FTS5、向量或混合检索，以真实同义改写召回及最终回答评测为准。

## 验证与限制

`tests/memory.test.ts` 使用临时 SQLite/文件仓储与 mock 模型，覆盖维度隔离、隐私、旧接口、修订、记事本、失败重试、重启续处理、索引旧版本/删除/故障和提供器替换；`tests/e2e/memory.spec.ts` 验证页签、人工管理与停用。完整检查见 [运行手册](memory-operations.md)。

目前没有真实 QQ 聊天上的提炼精确率、跨会话误报率或权重校准结果。模型可能误解玩笑、转述和冲突；词面检索会漏掉无共享字词的同义表达。暂存标记失败不会无限自动重试，需要修改或再次标记。中期到期是召回过滤，记录及修订仍保留于仓储，不能当作物理删除策略。
